# "합성 40장 = 실제 불량 몇 장" 실험 (11/25–11/26)

발표자료 v2의 RQ2(VisA)와 RQ3(SMT) "실제 몇 장" 슬라이드에 들어간 숫자를 만든 실행 스크립트, 분석 스크립트, 로그가 이 폴더에 있다.
모델과 지표는 팀 실험과 같다. 실험을 새로 설계하지 않았고, 비어 있던 칸(나누기, 실제 장수)만 채웠다.

## 무엇을 쟀나

실제 불량 K장에 합성 N장을 더한 성적을, **실제 불량만 쓴 곡선**에 놓고 "실제만으로 몇 장 쓴 것과 같은가"로 바꿔 읽는다.

- 실제만 곡선을 장수에 대해 "실제를 더 넣으면 나빠지지 않는다"는 조건으로 고르게 다듬은 뒤(PAVA, log2 K 위), 두 점 사이를 직선으로 잇는다.
- `<1`은 실제 최소 장수보다 나쁨, `>10`·`>32`는 곡선의 끝보다 좋음이다.
- VisA는 (나누기, PCB) 15단위를 2000번 복원 추출해 95% 구간을 냈다. SMT는 PCB 구분이 없어 나누기가 단위다.

| | VisA | SMT |
|---|---|---|
| 모델 | 위치 모델 + 촬영 조건 섞기 (`AnomalyDetection/ad/fair_ad.py`, `seg_aug`) | 위치 모델 (`AnomalyDetection/smt/seg_ad.py`, 2000 step) |
| 지표 | 배경 섞은 시험셋에서 과검 5%일 때 놓친 불량 (`fair_fnr5`) | 시험셋에서 과검 1%일 때 놓친 불량 (`fnr`) |
| 실제만 곡선 | K = 1, 2, 3, 4, 5, 6, 8, 10 × 나누기 5번 | K = 1, 2, 4, 8, 16, 32 × 나누기 5번 |
| 합성 | cTransGAN, SD+LoRA v3 × K 1·2·4 × 나누기 5번 (K8은 1번) | 사전 공정 SD+LoRA 나누기 5번, 나머지 3번 |

|---|---|---|---|---|
| 사전 | 1 | 25.9 / 19.9 | 14.8 (2.4장) | 16.3 (2.6장) |

| 납땜 | 1 | 80.2 | 77.2 (1.2장) | 72.5 (1.5장) |

- 실제가 적을 때(1–4장) 합성 40장은 실제를 1.1–2.6배 모은 효과가 있다. VisA와 SMT가 같은 흐름이다.
- 실제가 16장이면 공정마다 다르다. 사전 공정은 계속 좋아지고(실제 32장보다 나음), 납땜 공정은 나빠진다. 아래 합성 비율 실험 참고.
- SD+LoRA는 VisA 실제 1장에서 cTransGAN보다 2.6–4.0%p 더 놓친다(`ctg_vs_sd_visa.txt`). 2장부터는 둘이 비슷하다.

## 합성 비율 실험 (11/26, `run_smt_ratio.sh`)

위치 모델은 한 번에 정상 4장 + 불량 4장으로 배우고, 합성을 쓰면 불량 4장 중 2장(1/2)을 늘 합성으로 채운다. 실제가 많을 때도 합성 비중이 같아서,
납땜 16장에서 나빠진 이유가 합성 자체인지 비율인지 보려고 1/4(불량 4장 중 1장)로 줄여 다시 돌렸다. 두 공정 × 실제 1 · 4 · 16장 × 반복 0–2, 합성 40장.
(1/10은 4칸에서 반올림하면 0장이라 뜻이 없다.)

| 공정 · 생성 모델 | 실제 | 실제만 | 합성 1/2 | 합성 1/4 |
|---|---|---|---|---|
| 사전 · SD+LoRA | 1 / 4 / 16 | 19.9 / 10.6 / 3.4 | 13.6 / 6.3 / 1.6 | 13.3 / 6.7 / 1.9 |
| 사전 · cTransGAN | 1 / 4 / 16 | 19.9 / 10.6 / 3.4 | 16.3 / 6.3 / 1.9 | 17.3 / 7.7 / 1.8 |
| 납땜 · SD+LoRA | 1 / 4 / 16 | 80.2 / 56.4 / 40.9 | 77.2 / 49.4 / 49.6 | 75.1 / 50.2 / 42.1 |
| 납땜 · cTransGAN | 1 / 4 / 16 | 80.2 / 56.4 / 40.9 | 72.5 / 50.9 / 72.8 | 72.3 / 52.3 / 60.1 |

(놓친 불량 %, 원래 시험셋 정상 100장 중 1장 기준, 반복 3번 평균)

- 납땜 16장 SD+LoRA: 49.6% → 42.1%로 실제만(40.9%)과 비슷해졌다 → 해의 대부분은 비율 탓.
- 납땜 16장 cTransGAN: 72.8% → 60.1%, 여전히 실제만보다 19%p 나쁘다(반복 3번 모두) → 결함을 실제의 8.7배로 과장한 세트 자체가 문제(`results/ppt/gen_quality_smt_summary.md`).
- 실제 1 · 4장에서는 1/4로 줄여도 이득이 그대로다. 사전 공정 16장도 그대로 좋아진다.

## SMT 사진 단위 모델 비교 (11/27, `AnomalyDetection/smt/img_ad.py`)

질문: SMT 사진은 부품 하나 주변 512×512라 결함이 사진의 20–50%를 차지한다(상자 면적 중앙값 사전 29%, 납땜 47%. VisA는 0.2–0.5%).
그러면 위치 모델 없이 사진 단위 라벨만으로도 되지 않을까? 위치 모델(seg_ad.py 'none')과 같은 데이터 · 같은 확인으로
사진 단위 DevNet · MLP(고정 WRN50 이미지 임베딩 + 작은 머리, VisA와 같은 설정)를 돌렸다. 두 공정 × K 1 · 2 · 4 · 8 · 16 · 32 × 나누기 0–4.

| 사전 공정 (나누기 5번 평균) | K=1 | 4 | 16 |
|---|---|---|---|
| 놓친 불량 %: DevNet / MLP / 위치 모델 | 22.5 / 31.2 / 25.9 | 12.4 / 19.2 / 10.1 | 5.0 / 5.9 / 3.5 |
| 결함 지운 사진을 불량이라 함 % (낮을수록 결함을 봄) | 32.9 / 13.5 / 21.1 | 30.4 / 15.2 / 20.2 | 26.6 / 19.3 / 12.9 |
| 정상에 붙인 결함을 잡음 % (높을수록 좋음) | 49.7 / 27.8 / 42.2 | 50.7 / 32.1 / 61.5 | 49.2 / 33.5 / 63.3 |

| 납땜 공정 (나누기 5번 평균) | K=1 | 4 | 16 |
|---|---|---|---|
| 놓친 불량 %: DevNet / MLP / 위치 모델 | 77.0 / 77.0 / 78.0 | 58.7 / 55.7 / 55.7 | 46.7 / 39.9 / 40.6 |
| 결함 지운 사진을 불량이라 함 % | 9.2 / 5.3 / 6.6 | 12.4 / 10.4 / 6.8 | 14.5 / 13.3 / 8.0 |
| 정상에 붙인 결함을 잡음 % | 17.2 / 4.2 / 14.5 | 26.4 / 17.4 / 29.5 | 31.3 / 26.9 / 42.1 |

- 원래 시험 점수는 거의 비슷하다. 사전 K=1은 DevNet이 낫고(22.5 vs 25.9), K≥2는 위치 모델이 1.5–2.8%p 낫다. 납땜은 MLP가 위치 모델과 같다(K=32는 MLP 33.8 vs 39.7).
  VisA에서처럼 큰 차이(결함 바꾼 시험 87% vs 24%)는 SMT 원래 시험에서는 나오지 않는다.
- 결함을 보는지 확인하면 위치 모델이 낫다. 사전 공정 DevNet은 결함 지운 사진을 모든 K에서 27–33% 불량이라 하고(위치 모델보다 +10–14%p, 나누기 4–5/5),
  정상에 붙인 결함은 K가 늘어도 50% 안팎에 머문다. 위치 모델은 실제 장수가 늘면 63%까지 오른다. 납땜도 붙인 결함은 위치 모델이 가장 잘 잡는다(K=16 42% vs 31 · 27%).
- MLP는 결함 지운 사진 비율이 낮지만 붙인 결함도 덜 잡는다(전체적으로 불량이라고 덜 말한다). 낮은 DR만으로 결함을 본다고 할 수 없다.
- 정리: SMT처럼 결함이 크면 사진 단위 라벨로도 원래 시험 점수는 비슷하게 나온다. 하지만 결함을 보고 맞히는 정도(지운 · 붙인 사진)는 위치 모델이 낫고, 실제 장수가 늘수록 그 차이가 커진다.
  SMT에는 결함 바꾼 시험셋이 없어서 이 확인은 학습 후보(pool) 불량 192 · 384장으로만 했다.

결과: `AnomalyDetection/results/smt/img_ad_{pre,solder}.csv`, 비교 표 `cmp_img_seg_smt.txt` (`python AnomalyDetection/results/logs_jh/cmp_img_seg_smt.py`),
실행 로그 `smt_img_ad.log`. 두 공정 전체가 A100에서 약 5분.

### 어디를 보고 불량이라 하나 (Grad-CAM, `AnomalyDetection/smt/cam.py`)

사진 단위 DevNet의 Grad-CAM(WRN50 layer3, 32×32)과 위치 모델이 내놓는 결함 지도를 시험셋 불량 전체(사전 300, 납땜 540장)에서 비교했다.
나누기 0, K=1 · 16. 결함 영역 = 불량 상자를 8px 넓힌 것. 지도가 사진 전체에 고르게 퍼지면 "영역 안 비율"은 영역 면적과 같아진다(= 무작위 기준).

| 시험 불량 평균 | 지도 중 영역 안 비율 | 최고점이 영역 안 | 무작위 기준(면적) | 과검 1%에서 잡은 비율 |
|---|---|---|---|---|
| 사전 K=1: DevNet / 위치 모델 | 0.61 / 0.75 | 54% / 78% | 0.43 | 79% / 80% |
| 사전 K=16 | 0.58 / 0.86 | 47% / 99% | 0.43 | 95% / 98% |
| 납땜 K=1 | 0.47 / 0.61 | 46% / 58% | 0.48 | 24% / 17% |
| 납땜 K=16 | 0.50 / 0.74 | 41% / 95% | 0.48 | 52% / 61% |

- 납땜 DevNet은 무작위 기준과 같다(0.50 vs 0.48). 유형별로 봐도 12종 모두 영역 면적과 차이가 0.1 미만이다. 실제 장수를 16장으로 늘려도 그대로다.
- 사전 DevNet은 기준보다 조금 위(0.58–0.61 vs 0.43)지만 K=16에서 오히려 내려가고, 최고점은 절반만 영역 안이다. 그런데 K=16에서 불량 95%를 잡는다.
  결함이 아닌 곳을 보고도 맞힌다는 뜻이고, 결함 지운 사진을 27–33% 불량이라 한 결과와 맞는다.
- 위치 모델은 K가 늘면 결함에 모인다. K=16에서 최고점이 사전 99%, 납땜 95% 영역 안이다.
- 주의: Grad-CAM은 사진 단위 점수를 사후에 풀어 본 것이고, 위치 모델 지도는 모델이 직접 내는 출력이다. 같은 잣대가 아니므로 숫자 크기보다는
  "무작위 기준보다 위인가, K가 늘면 좋아지는가"를 본다. VisA DevNet도 같은 방식으로 영역 안 4%(기준 3%)였다.

결과: `AnomalyDetection/results/smt/cam_K{1,16}_seed0_{pre,solder}.csv` (사진마다 지표), 실행 로그 `smt_cam_{pre,solder}_K{1,16}.log`.
그림은 AIHub 사진이 들어 있어 git에 올리지 않는다(`Dataset/aihub_smt/cam/`, `--redraw`로 학습 없이 다시 그림). 한 칸에 A100에서 약 6분(위치 모델 학습이 대부분).

## 다시 돌리기

저장소 루트에서 실행한다. 파이썬은 `PY`로 넘긴다(기본 `python`).

```bash
PY=python bash AnomalyDetection/results/logs_jh/run_visa_equiv.sh   # VisA 원본이 Dataset/visa/VisA_official/VisA_PCB에 있어야 함. 다시 돌릴 칸의 결과 csv · manifest를 먼저 지운다
PY=python bash AnomalyDetection/results/logs_jh/run_smt_equiv.sh    # AIHub SMT 원본과 생성 세트가 있어야 함 (원본은 AIHub에서 받고, 생성 세트는 다시 만든다)
python AnomalyDetection/results/logs_jh/equiv_visa.py ctg
python AnomalyDetection/results/logs_jh/equiv_smt.py
```

분석 스크립트는 저장소에 있는 결과 csv만 읽으므로 데이터 없이도 바로 돌아간다. 저장된 `*.txt`와 같은 값이 나오는 것을 확인했다.
A100 80GB 한 장에서 VisA 실행은 약 14시간, SMT 실행은 약 1시간 걸렸다.
