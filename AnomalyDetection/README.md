## 0. 한 줄 요약

신규 라인처럼 **정상 사진은 많고 불량 사진은 결함 종류마다 몇 장뿐인 상황**을 가정합니다. 이 연구는 두 가지에 숫자로 답합니다.

- 불량 사진을 학습에 넣으면 정상만으로 학습한 방법(PatchCore)보다 탐지가 **유의미하게 좋아지는지**
- 좋아진다면 **불량을 몇 장(K) 넣는 것이 가장 적절한지**

또한 Augmentation 팀이 만든 증강·생성 불량을 더했을 때 필요한 실제 불량 수가 **몇 장 줄어드는지**(등가 샘플 수)를 잽니다.

### 연구 질문

| 번호   | 질문                                                             | 답의 형태                                        |
| ------ | ---------------------------------------------------------------- | ------------------------------------------------ |
| RQ1    | 불량을 학습에 넣으면 정상만 쓰는 방법보다 유의미하게 좋아지는가? | K=0 PatchCore 대비 성능 차이와 통계 검정 결과    |
| RQ2    | 몇 장이 적절한가?                                                | 교차 K, 목표 K\*, 수확체감 K (6.3절)             |
| RQ3    | 증강·생성이 실제 불량 몇 장을 대신하는가?                       | 등가 샘플 수 ("실제 2장 + 생성 = 실제 6장 수준") |
| (보조) | 탐지한 불량의 결함 종류를 맞히는가?                              | 종류 분류 macro-F1                               |

## 2. 데이터와 분할

### 2.1 사용하는 데이터와 PCB4를 빼는 이유

VisA의 PCB1–3은 결함 종류가 4가지로 같습니다: Bent, Melt, Scratch, Missing. 원본 마스크의 픽셀값 1–4가 종류 ID입니다. 공식 `prepare_data.py`는 이 값을 0/255로 바꿔 종류 정보를 지우므로, **원본 `Data/Masks`를 직접 읽습니다.**

아래는 직접 집계한 결함 종류별 불량 이미지 수입니다. 괄호 밖은 그 종류가 들어 있는 모든 이미지, 괄호 안은 그 종류 하나만 들어 있는 이미지입니다.

|      | 정상  | Bent              | Melt    | Scratch | Missing | 여러 종류가 섞인 이미지 |
| ---- | ----- | ----------------- | ------- | ------- | ------- | ----------------------- |
| PCB1 | 1,004 | 15 (14)           | 54 (46) | 21 (14) | 20 (17) | 9                       |
| PCB2 | 1,001 | 15 (**12**) | 55 (48) | 20 (14) | 19 (17) | 9                       |
| PCB3 | 1,006 | 20 (19)           | 43 (38) | 25 (20) | 20 (16) | 7                       |

PCB4를 빼는 이유는 두 가지입니다.

- Burnt는 8장이고 그중 Burnt만 들어 있는 이미지는 2장입니다. Wrong Place도 단일 종류 이미지가 2장뿐입니다.
- 이미지의 56%에 여러 종류가 섞여 있어 종류별로 K장을 뽑기 어렵습니다.

참고: "K=9까지인 이유는 어떤 종류가 9장이라서"라는 기억은 데이터와 맞지 않습니다. 정확히 9장인 종류는 없고, K 상한을 결정하는 것은 **PCB2 Bent의 단일 종류 12장**입니다.

### 2.2 분할 규칙 `[결정]`

분할은 한 번 만들어 고정하고, 모든 K, 시드, 증강 조건, 모델이 **같은 시험셋**을 씁니다.

**불량 이미지** (PCB마다, 결함 종류마다 따로 적용)

## 3. K 설계

### 3.1 K의 정의 `[결정]`

**K = PCB 1개(= 라인 1개)에서 결함 종류당 실제 불량 장수입니다.** 예를 들어 K=2이면 PCB1의 Bent 2장, Melt 2장, Scratch 2장, Missing 2장으로 총 8장입니다.

이렇게 정한 이유는 세 가지입니다.

- 이상탐지는 관례적으로 제품(라인)마다 모델을 따로 학습합니다. 새 라인 하나를 띄우는 상황과 같습니다.
- 셋업 기간은 **가장 드문 결함 종류의 장수**가 정합니다. 종류당 장수로 정의해야 비용으로 바로 환산할 수 있습니다.
- PCB1–3이 같은 실험을 세 번 반복한 셈이 되어 결과의 신뢰도가 올라갑니다.

### 3.2 주 실험: K ∈ {0, 1, 2, 4, 8}, 시드 5개 `[결정]`

| K | 라인당 불량 총수 | 의미                                                         |
| - | ---------------- | ------------------------------------------------------------ |
| 0 | 0                | 정상만 쓰는 기준점입니다(PatchCore, KNN, DRAEM-합성).        |
| 1 | 4                | 첫 불량 1장의 효과를 봅니다. 한계 효과가 가장 큰 구간입니다. |
| 2 | 8                |                                                              |
| 4 | 16               |                                                              |
| 8 | 32               | 상한입니다. PCB2 Bent 풀이 8장이라 더 늘릴 수 없습니다.      |

**5개 지점으로 충분하다고 보는 이유**

- **로그 간격(2배씩)** 을 씁니다. 학습 곡선은 앞쪽에서 크게 변하고 뒤로 갈수록 평평해집니다. 처음 제안한 1, 3, 5, 7, 9는 평평한 뒤쪽에 지점을 낭비합니다. 2배 간격이면 "불량을 두 배로 모으면 얼마나 좋아지나"를 같은 기준으로 비교할 수 있어 수확체감을 판단하기에 맞습니다.
- 곡선의 모양(감소 후 평탄)과 PatchCore와의 교차점을 잡으려면 기준점 1개와 K>0 지점 4개면 됩니다. 지점을 늘리면 실행 비용은 비례해서 늘지만, 이웃한 지점 사이의 차이는 시드 간 분산 안에 묻힙니다.
- **추가 후보 K=3, 6** `[보류]`: 교차점이나 꺾이는 지점이 2–4 또는 4–8 사이에 있으면 그 구간만 추가로 돌립니다.

**시드 5개가 필요한 이유**

- K가 작으면 어떤 불량을 뽑았는지에 따라 성능이 크게 흔들립니다.
- 한 지점마다 3 PCB × 5 시드 = **15번 실행**하므로, 같은 PCB와 시드끼리 짝지어 비교(paired)할 수 있습니다.
- 대략적인 추정입니다. 실행 간 표준편차가 5%p라면 평균 차이의 표준오차는 약 1.3%p입니다. 그러면 3%p 안팎의 차이를 구분할 수 있습니다. 이 추정은 파일럿 결과로 다시 확인합니다.
- 같은 시드 안에서는 K=1 ⊂ 2 ⊂ 4 ⊂ 8이 되도록 앞에서부터 뽑습니다. 이렇게 하면 K를 늘린 효과가 어떤 샘플을 뽑았느냐와 섞이지 않습니다.
- K=8에서 PCB2 Bent는 풀 8장을 모두 쓰므로 시드가 달라도 같은 이미지가 들어갑니다. 해석할 때 이 점을 감안합니다.

### 3.3 보조 실험(PCB1–3 합침): 제외 `[보류]`

**결정 (11/11).** 보조 실험은 추가 요청이 있기 전까지 이번 프로젝트에서 **제외**합니다. Augmentation 팀에 copy-paste·diffusion 어느 쪽도 보조 실험용 생성을 요청하지 않습니다. 모든 실험이 끝났거나 중간에 필요하다고 판단되면 다시 검토합니다.

- **남는 한계.** 주 실험의 곡선은 K=8에서 끝나므로, "실제 k장 + 생성"이 실제 8장보다 좋으면 등가 샘플 수를 "**≥ 8**"(하한)으로만 보고합니다(6.4절).
- **다시 검토할 때의 참고.** 원래 안은 PCB1–3을 한 라인으로 보고 K ∈ {0, 1, 2, 4, 8, 16, 24}로 모델 하나를 학습하는 것이었습니다. Augmentation 팀은 이 경우에도 diffusion은 빼고 copy-paste만 지원하자고 제안했습니다. 같은 이름의 결함도 PCB마다 모습이 달라서(missing: pcb1 센서 망, pcb2 칩, pcb3 핀) 합친 소수 샘플로 생성 모델 하나를 학습하는 의미가 약하다는 이유입니다. 다시 열 경우 이 제안을 그대로 따릅니다.

## 4. 모델

### 4.1 비교의 뼈대

RQ1(정상만 vs 불량 추가)은 두 가지 방식으로 공정하게 비교합니다.

- **모델 사이 비교**: PatchCore K=0과 불량을 쓰는 모델의 K>0을 비교합니다. "현장 표준 방식 대비 얼마나 좋아지나"에 답합니다.
- **모델 안 비교**: 같은 모델의 K=0과 K>0을 비교합니다. 구조가 같으므로 차이는 순수하게 **불량 데이터의 효과**입니다. KNN+MLP와 DRAEM이 이 역할을 맡습니다.

(해석 확인 필요: 10절)                                               |
| 추가 1 | **미세조정 CNN 분류기** (ResNet-18 등)               | 전이학습(L05)을 그대로 씁니다. 정상과 K장으로 지도 학습하며, 클래스 가중치나 오버샘플링으로 불균형을 다룹니다.                                    | 정상 + 불량                                            | 증강 효과가 가장 직접 드러나는 "보통의 지도학습"입니다. 2단계 종류 분류로 쉽게 확장됩니다.                                                                         |
| 추가 2 | **DRAEM** (ICCV 2021)                                | 오토인코더(L05)로 복원하는 부분과 분할망으로 판별하는 부분으로 이루어집니다. 정상 이미지에 Perlin 노이즈로 가짜 결함을 합성해 학습합니다.         | K=0이면 정상 + 합성 결함, K>0이면 실제·생성 결함 추가 | **모델 안 비교** 역할입니다. "노이즈 합성, 실제 K장, 생성 결함 중 무엇을 넣어야 하나"를 같은 구조에서 비교할 수 있어 Augmentation 팀 주제와 바로 이어집니다. |
| 추가 3 | **DevNet** (KDD 2019), 여력이 있으면 DRA (CVPR 2022) | "정상은 많고 라벨 붙은 불량은 몇 장뿐"인 상황을 위한 모델입니다. 불량의 점수가 정상 점수 분포에서 크게 벗어나도록 학습합니다(deviation loss).     | 정상 + 불량                                            | 소수 불량 학습 전용 계열의 대표입니다. 손실 하나로 설명할 수 있습니다.                                                                                             |

**뺀 후보**

- EfficientAD, PaDiM: 정상만 쓰는 모델이라 PatchCore와 역할이 겹칩니다.
- BGAD, AHL: normalizing flow나 메타러닝이 들어가 발표에서 설명하기 어렵습니다.
- WinCLIP, AnomalyCLIP: 언어모델 프롬프트가 필요해 주제에서 벗어납니다.

**선택지**: PatchCore의 메모리에 불량 K장의 패치도 넣고 "정상까지 거리 − 불량까지 거리"로 점수를 매기는 변형이 있습니다. 구현이 거의 공짜이고 AnomalousPatchCore(2024)와 같은 방향입니다. 시간이 나면 추가합니다.

### 4.3 2단계 구조 `[결정]`

1. **1단계 (주): 정상/불량 이진 탐지.** 모든 모델과 모든 K에 적용합니다. **결함 종류별 성능은 이 탐지기의 종류별 미검률**로 보여 줍니다. 그래서 다중 클래스 분류기가 없어도 종류별 분석을 할 수 있습니다.
2. **2단계 (보조): 결함 종류 분류.** 불량으로 판정된 이미지를 4종류로 분류합니다. K≥1에서만 가능하고, 단일 종류 시험 이미지에서만 평가합니다. 주 모델의 특징이나 분류기 헤드로 구현합니다.

처음 생각했던 "다중 클래스로 하다가 잘 안 되면 이진으로 바꾼다"는 순서가 반대가 되었습니다. K=0에서는 종류를 알 수 없고 섞인 이미지는 정답 라벨이 하나로 정해지지 않기 때문입니다.

## 5. 증강 조건과 누수 규칙

### 5.1 증강 조건

| 조건          | 내용                                                                                                             | 만드는 쪽                                    |
| ------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `none`      | 실제 K장만 씁니다.                                                                                               | —                                           |
| `classic`   | 이미지 전체에 거는 기본 변환: **회전 ±3°, 이동 ±2%, 밝기·대비 ±10%, 가우시안 블러(p=0.2, σ≤1)**. 뒤집기는 넣지 않습니다(기판 전체를 뒤집으면 라인에 없는 부품 배치가 됨). 임베딩 모델은 불량마다 10개·정상마다 1개의 증강본을 더하고, 분류기는 학습 중 매번 적용합니다. 코드: `ad/augment.py` | AnomalyDetection 팀 (9절 ⑥, Augmentation 팀 잠정안 ±10°·상하 반전보다 보수적으로 정함) |
| `copypaste` | 실제 결함을 오려 정상 기판의 **같은 부품 위치**에 붙입니다. 먼저 결함 원본과 바탕의 기판 위치를 맞춥니다(기판 마스크 phase correlation + 회색조 NCC로 0°/180° 판정. **PCB1은 약 75%가 핀이 위, 25%가 핀이 아래인 180° 회전 사진이 섞여 있음**, PCB2·3도 수십 px씩 이동). 위치 흔들림은 bent·missing ±5px, melt·scratch ±30px. 결함 패치에는 **좌우 반전(p=0.5), 회전 ±3°, 크기 ±10%, 밝기·대비 ±5%** 만 겁니다(11/11 변경, 큰 회전 없음). 원본과 같은 JPEG quality 75·4:2:0으로 저장하고 마스크는 PNG(종류 ID 1–4). 코드: `Augmentation/visa_pcb/src/generate/k_copypaste.py`의 `PATCH_AUG` | Augmentation 팀 코드, 증강 설정은 AnomalyDetection 팀이 수정 |
| `ctransgan` | **생성 조건의 주 방법(1단계). 일주일 뒤(11/18 전후) 받아서 추가.** cTransGAN으로 결함 패치를 생성해 정상 기판에 넣습니다. 조건마다 해당 K장으로 새로 학습합니다(T4에서 조건당 약 13분). | Augmentation 팀                              |
| `sd_lora`   | SD inpainting + LoRA. ctransgan 1단계를 마치고 시간이 남으면 추가합니다(선택).                                 | Augmentation 팀                              |

- `classic` 변환은 **정상 이미지에도 똑같이** 적용합니다. 불량에만 적용하면 모델이 결함이 아니라 "변환 흔적이 있으면 불량"이라는 지름길을 배웁니다.
- copy-paste의 한계: 원래 있던 곧은 핀·부품을 지우지 않고 위에 덮으므로, bent·missing 일부 샘플에는 원래 핀이 겹쳐 보입니다. 정렬 전(11/11 첫 버전)에는 핀이 기판 밖 바닥에 붙는 샘플이 있었고, 그 결과물은 지우고 다시 만들었습니다.
- 생성 이미지에도 같은 위험이 있습니다(생성 특유의 흔적). 시험셋은 실제 이미지뿐이라 지름길을 배우면 점수가 떨어져 드러나지만, 해석할 때 주의합니다.

### 5.2 누수 규칙 (위반하면 결과 전체가 무효) `[결정]`

1. 생성 모델과 copy-paste의 **결함 소스는 해당 `train_K{k}_seed{s}.csv`의 불량만** 씁니다. K=2 조건의 생성 모델은 그 2장만 봐야 합니다. 풀 10장이나 불량 100장 전체로 학습한 생성 모델을 여러 K에 돌려쓰면 안 됩니다.
2. 주 실험은 **PCB별**입니다. PCB1 조건의 생성 모델은 PCB1의 K장만 봅니다.
3. 결함을 붙이거나 그려 넣을 **정상 바탕 이미지는 `train_normal`에서만** 가져옵니다. `val_normal`과 `test`의 정상은 쓰지 않습니다.
4. 결과를 기록하기 전에 manifest의 `source_image`와 바탕 이미지가 `test.csv`, `val_normal.csv`에 없는지 자동으로 검사합니다.
5. Augmentation 팀이 33장 비교 실험(gen_train)으로 **이미 학습한 체크포인트(cTransGAN 등)는 K 실험에 쓰지 않습니다.** 그 33장과 gen_train 정상에는 우리 시험셋 이미지가 들어 있을 수 있습니다. K 실험의 생성 모델은 조건마다 해당 K장과 `train_normal`만으로 새로 학습합니다. 사전학습 단계가 있다면 그 단계도 `train_normal`만 씁니다.

### 5.3 생성 범위 `[결정]`

생성 모델(1단계는 `ctransgan`)은 조건마다 따로 학습해야 해서 가장 비쌉니다. 그래서 우선순위를 둡니다. 아래 단계는 `ctransgan` 기준이고, `sd_lora`는 1단계 뒤 여유가 있을 때 추가합니다. 2단계(시드 추가)와 `sd_lora` 중 무엇을 먼저 할지는 9.1절을 보세요.

| 단계                   | 범위                                                         | 생성 모델 학습 횟수               | 목적                                            |
| ---------------------- | ------------------------------------------------------------ | --------------------------------- | ----------------------------------------------- |
| **1단계 (필수)** | 주 실험, PCB1–3 × K ∈ {1, 2, 4} × 시드 0                 | 9회                               | RQ3의 핵심 숫자                                 |
| 2단계                  | 같은 조건에 시드 1, 2 추가                                   | +18회                             | 신뢰구간                                        |
| 3단계                  | 주 실험 K=8, 시드 0                                          | +3회                              | 많이 모았을 때의 효과                           |

- 보조 실험이 제외되어 3단계에서 PCB를 합친 생성 모델은 만들지 않습니다(3.3절).
- K=1은 GAN이 볼 불량이 종류당 1장뿐이라 품질이 낮을 수 있습니다. Augmentation 팀은 K=1을 먼저 돌리고, 품질이 나빠도 그대로 넘깁니다. 그 경우 "K=1에서는 생성이 도움이 안 된다"는 것 자체가 결과입니다.
- LoRA 하나에 결함 종류 4가지를 담고 프롬프트로 종류를 구분하면, 조건 하나에 생성 모델 하나로 충분합니다.
- `copypaste`는 생성 비용이 거의 없으므로 **주 실험의 모든 K {1, 2, 4, 8} × 시드 5개 × PCB1–3 = 60개 조건**을 만듭니다.
- Augmentation 팀은 생성 품질(FID, 육안 검사)을 따로 측정해 보고합니다. AnomalyDetection 팀 일정과는 별개로 진행합니다(9절 ⑩).
- **생성 장수는 방법끼리 같게** 맞춥니다. copy-paste와 diffusion을 같은 장수로 비교해야 공정합니다. 제안값은 조건당 **결함 종류별 40장**(PCB당 160장, 정상 학습 500장 대비)입니다. 장수를 바꿔 보는 실험(10/40/160)은 Augmentation 팀이 선택할 수 있습니다.
- **확정 (11/11)**: ctransgan도 조건당 종류별 40장(PCB당 160장)으로 맞춥니다. 방법 간 비교는 같은 장수에서 하고, 장수를 늘리는 효과는 여유가 되면 ⑦의 선택 실험(10/40/160)으로 따로 봅니다.

## 6. 평가

### 6.1 지표

| 지표                             | 계산                                                                                          | 용도                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| **과검률 1%에서의 미검률** | 시험 ROC에서 과검률(FPR) = 1%인 지점의 미검률(FNR = 1 − 재현율)                              | **주 지표.** K 곡선과 K\* 판정에 씁니다.          |
| 종류별 / macro 미검률            | 같은 임계값에서 결함 종류마다 계산한 미검률, 그리고 4종류의 평균                              | Melt가 시험셋의 절반 이상이므로 macro 값을 같이 봅니다. |
| 실운영 방식 미검률·과검률       | `val_normal`에서 과검률 1%가 되도록 임계값을 정하고, 시험셋에서 실제로 나온 과검률과 미검률 | 현장 현실성을 보여 주는 보조 지표입니다.                |
| 이미지 AUROC, AP                 | 임계값 없이 계산합니다. AP는 불균형에 강합니다.                                               | 선행 연구와 비교할 때 씁니다.                           |
| 종류 분류 macro-F1, 혼동행렬     | 2단계                                                                                         | 보조 지표입니다.                                        |

**AUROC만 쓰지 않는 이유**: VisA PCB에서 PatchCore의 AUROC는 이미 높게 보고됩니다. AUROC 0.98이어도 과검률 1% 지점의 미검률은 20~30%일 수 있습니다. 현장에서 중요한 것은 그 지점이고, 모델 사이의 차이도 그 지점에서 더 잘 드러납니다.

### 6.2 "유의미한 개선"의 판정 `[제안]`

- 같은 (PCB, 시드)끼리 짝지은 15쌍으로 미검률 차이를 계산합니다.
- 두 조건을 모두 만족하면 유의미하다고 판정합니다.
  - **통계적 조건**: 짝지은 부트스트랩 95% 신뢰구간이 0을 포함하지 않습니다. 보조로 Wilcoxon 부호순위 검정을 함께 봅니다.
  - **실용적 조건**: 미검률이 **2%p 이상** 줄어듭니다.

### 6.3 "적절한 K"의 세 가지 정의

| 이름                 | 정의                                                      | 현장 의미                                    |
| -------------------- | --------------------------------------------------------- | -------------------------------------------- |
| **교차 K**     | PatchCore K=0보다 유의미하게 좋아지는 가장 작은 K         | 이만큼은 모아야 불량을 넣는 의미가 있습니다. |
| **목표 K\***   | 미검률(과검률 1%)의 평균이 목표값 이하가 되는 가장 작은 K | 사람 대신 AI에 맡길 수 있는 시점입니다.      |
| **수확체감 K** | 그 이후로는 K를 두 배로 늘려도 개선이 유의미하지 않은 K   | 더 모아도 효과가 적은 지점입니다.            |

- 목표값은 파일럿 결과를 보고 정합니다 `[보류]`. 후보는 미검률 5% 또는 10%입니다.
- "가장 적절한 K"는 세 값을 함께 놓고 결정합니다. 예: "교차 1장, 목표 4장, 수확체감 4장 → 4장이 적절".

### 6.4 등가 샘플 수

- 실제 불량만 쓴 곡선(`none`)을 log K 축에서 선형 보간합니다. "K=k + 증강"의 성능이 이 곡선에서 어느 K에 해당하는지 읽습니다.
- 신뢰구간은 시드 부트스트랩으로 냅니다.
- 곡선의 끝(K=8)을 넘으면 "≥ 8"처럼 하한으로 보고합니다. 보조 실험을 제외했으므로 이 천장은 그대로 남습니다.

### 6.5 현장 환산

- 필요한 생산량 ≈ K ÷ (불량률 × 그 결함 종류의 비중)
- 예: 불량률 0.1%, Bent가 불량의 15%라면, Bent 4장을 모으는 데 약 4 / 0.00015 ≈ **26,700개**를 생산해야 합니다.
- 셋업 기간은 **가장 드문 종류**가 정합니다.
- 종류 비중은 VisA 집계를 대용으로 쓰며 실제 공정 값이 아니라는 점을 명시합니다.

## 8. 최종 산출물 (발표 구성)

1. **K 곡선** (핵심 그림): 가로축 K(로그), 세로축 미검률(과검률 1%). 모델별 선과 95% 신뢰구간 띠, PatchCore 수평 점선을 그리고, 교차 K·목표 K\*·수확체감 K를 표시합니다. → RQ1, RQ2
2. **증강 비교 그림**: 주 모델에서 증강 방법별 선을 그리고 등가 샘플 수를 화살표로 표시합니다. → RQ3
3. **요약 표**: 모델 × 증강별 교차 K / K\* / 수확체감 K / 등가 샘플 수
4. **결함 종류 × K 미검률 히트맵**: 어떤 결함이 가장 많은 실제 샘플을 요구하는지 보여 줍니다.
5. **현장 환산 표**: 가장 드문 종류 기준으로 필요한 생산량을 계산하고, 증강으로 줄어드는 셋업 생산량을 보여 줍니다.
6. 놓친 사례의 이상 맵과 한 문장 결론. 예: "PCB 라인에서 불량을 종류당 4장 모으면 PatchCore 대비 미검이 X%p 줄고, copy-paste를 더하면 2장으로 충분하다."

### 9.1 ⑤ 생성 방법: cTransGAN `[결정]` (11/11)

- **1단계는 cTransGAN**으로 합니다. 범위는 PCB1–3 × K {1, 2, 4} × 시드 0, 9개 조건입니다. 조건마다 해당 K장으로만 새로 학습하고, 기존 33장 체크포인트는 쓰지 않습니다(누수 규칙 5번).
- T4에서 조건당 약 13분 걸려서 11/17 마감은 가능합니다.
- K=1은 품질이 낮을 수 있습니다. 먼저 돌려 보고 결과를 그대로 넘깁니다(5.3절).
- 증강 이름은 `ctransgan`입니다(`results.csv`의 `aug` 열, `Dataset/generated/ctransgan/`).
- **SD+LoRA**는 1단계를 마치고 시간이 남으면 추가합니다. 5.3절의 2단계(ctransgan 시드 1, 2 추가)와 SD+LoRA 중 무엇을 먼저 할지는 아직 정하지 않았습니다. AnomalyDetection 팀 의견은 **ctransgan 시드 추가가 먼저**입니다. 등가 샘플 수의 신뢰구간이 RQ3의 핵심이기 때문입니다.

## 11. 선행 연구와 차별점

| 연구                                                                                      | 내용                                                                                                                                                             | 우리와의 관계                                                 |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| PatchCore (Roth et al., CVPR 2022)                                                        | 정상만 쓰는 패치 메모리 방식입니다. VisA PCB에서 이미지 AUROC가 약 95–99%로 보고됩니다(원문 확인 필요).                                                         | 기준선                                                        |
| DRAEM (Zavrtanik et al., ICCV 2021)                                                       | 합성 결함으로 학습하는 복원·판별 모델입니다. VisA 평균 이미지 AUROC가 80%대 후반으로 보고됩니다(원문 확인 필요).                                                | 모델 안 비교                                                  |
| DevNet (Pang et al., KDD 2019), DRA (Ding et al., CVPR 2022), AHL (Zhu et al., CVPR 2024) | 소수 불량 지도 이상탐지입니다. 보통 불량 1장과 10장 두 지점에서 AUROC로 보고합니다. AHL 논문에 따르면 AHL이 DRA와 DevNet보다 AUC를 최대 4%p, 9%p 높입니다.       | 우리는 K 곡선 전체와 과검률 1% 지점의 미검률로 다시 잽니다.   |
| Baitieva et al. (CVPR 2024)                                                               | 산업 영상에서 지도 이상탐지와 비지도 이상탐지를 비교했습니다. 보충자료에서 "VisA는 클래스당 결함 종류가 적어서 지도 학습 결과(99.7)가 높게 나온다"고 지적합니다. | 결함 종류별로 나눠 평가하는 우리 설계가 이 약점을 보완합니다. |
| AnomalousPatchCore (2024)                                                                 | 소수 불량으로 PatchCore의 특징 추출기를 개선했습니다.                                                                                                            | K 곡선과 증강 비교는 다루지 않았습니다.                       |

**차별점**: 모델 자체의 새로움은 주장하지 않습니다. 우리가 내세우는 것은 다음 세 가지입니다.

1. 정상만 쓰는 방법 대 K장 지도 학습의 **교차 지점**
2. **과검률 1%에서의 미검률**로 그린 결함 종류별 K 곡선
3. 증강 방법별 **등가 샘플 수와 셋업 생산량 환산**

copy-paste가 diffusion을 이겨도 "이 조건에서는 비싼 생성 모델이 필요 없다"는 현장의 답이 됩니다.

| PatchCore는 불량을 쓰지 않아 K에 따라 변하지 않습니다. | 오히려 그 점이 목적입니다. "정상만 학습"과 "불량도 학습"을 비교하는 것이 이 연구의 핵심이므로, PatchCore는 수평 기준선으로 씁니다.                    |
| PatchCore가 K=0에서 이미 목표를 넘을 위험              | 과검률 1%에서의 미검률을 주 지표로 쓰고, 파일럿으로 먼저 확인한 뒤 다시 검토합니다.                                                                   |
| 생성 데이터 누수와 diffusion 비용                      | 누수 규칙(5.2절)과 단계별 생성 범위(5.3절)를 AnomalyDetection 팀이 제안하고 Augmentation 팀과 합의합니다.                                             |
| K 정의가 이전 문서(PCB 합침 5/10/20)와 다름            | 이전 문서는 폐기했습니다. K는 이 문서의 정의(PCB별, 종류당)를 따릅니다.                                                                               |
| 다중 클래스와 K=0이 함께 성립하지 않음                 | 이진 탐지를 주로, 종류 분류를 보조로 하는 2단계 구조로 진행합니다.                                                                                    |
| 등가 샘플 수의 천장(K=8)                               | PCB1–3을 합친 보조 실험(K는 24까지)으로 보완합니다. → 11/11에 보조 실험을 제외해 "≥ 8" 하한 보고로 바뀜                                              |

## 13. 실행 결과 (진행 중)

코드: `AnomalyDetection/ad/` (data, features, augment, models, eval, run, analyze). 결과: `results/results.csv`, `results/results_per_type.csv`, 로그 `results/logs/`.
로컬 실행 환경: Apple Silicon(MPS), 메모리 16GB. 원본은 `Dataset/visa/raw/`(VisA_20220922.tar의 pcb1–3, git 제외).

### 13.1 파일럿: PatchCore K=0, 해상도 256 vs 512 (11/11)

| PCB  | 256: FNR@1% | 256: AUROC | 512: FNR@1% | 512: macro FNR | 512: AUROC | 512: 실운영 FNR / FPR |
| ---- | ----------- | ---------- | ----------- | -------------- | ---------- | --------------------- |
| pcb1 | 0.300 | 0.965 | **0.067** | 0.042 | 0.9971 | 0.150 / 0.000 |
| pcb2 | 0.452 | 0.933 | **0.210** | 0.252 | 0.9648 | 0.242 / 0.010 |
| pcb3 | 0.517 | 0.964 | **0.183** | 0.220 | 0.9883 | 0.150 / 0.016 |
| 평균 | 0.423 | 0.954 | **0.153** | 0.171 | 0.9834 | |

- **해상도는 512로 정합니다** `[결정]`. 256에서는 결함(이미지 면적 0.2–0.5%)이 뭉개져 미검률이 2–4배 높습니다.
- AUROC는 0.96–0.997로 높지만, 과검률 1%에서 PCB2·3은 불량의 약 20%를 놓칩니다. 불량을 넣어 개선할 여지가 남아 있습니다(RQ1).
- 목표 미검률 `[보류]`: PatchCore 평균이 약 15%이므로, 후보 10%와 5% 중 **5%** 를 제안합니다(10%는 PCB1에서 이미 달성).
- 실행 시간: 512에서 PCB당 약 16분(첫 실행, 이미지 캐시 포함).

### 13.2 baseline: 실제 불량만(`none`), 해상도 512, 3 PCB × 시드 5 (11/11)

전체 평균 FNR@FPR1% (괄호: macro). PatchCore K=0 = **0.153** (0.171).

| 모델      | K=0           | K=1           | K=2           | K=4           | K=8               |
| --------- | ------------- | ------------- | ------------- | ------------- | ----------------- |
| PatchCore | 0.153 (0.171) | —             | —             | —             | —                 |
| KNN+MLP   | 0.448 (0.377) | 0.563 (0.509) | 0.410 (0.363) | 0.313 (0.269) | 0.177 (0.145)     |
| DevNet    | —             | 0.341 (0.300) | 0.234 (0.194) | 0.153 (0.118) | **0.093** (0.073) |

짝지은 비교(15쌍, 부트스트랩 95% CI, `python -m AnomalyDetection.ad.analyze --res 512`):

| 비교                         | 미검률 개선 (양수 = 좋아짐) | 판정 |
| ---------------------------- | --------------------------- | ---- |
| DevNet K=4 vs PatchCore      | +0.001 [−0.057, +0.061]     | 차이 없음 |
| DevNet K=8 vs PatchCore      | **+0.060 [+0.016, +0.108]** | **유의미 (교차 K = 8)** |
| DevNet K=1→2 / 2→4 / 4→8     | +0.107 / +0.081 / +0.060 (모두 CI > 0) | 2배로 늘릴 때마다 유의미 → K ≤ 8에서 수확체감 없음 |
| KNN+MLP K=8 vs PatchCore     | −0.024 [−0.090, +0.048]     | 넘지 못함 |

결함 종류별 FNR@FPR1% (DevNet none, 3 PCB × 시드 평균):

| 종류    | PatchCore | K=1   | K=2   | K=4   | K=8   |
| ------- | --------- | ----- | ----- | ----- | ----- |
| Bent    | 0.095     | 0.141 | **0.020** | 0.007 | 0.000 |
| Missing | 0.315     | 0.317 | 0.180 | **0.093** | 0.030 |
| Melt    | 0.153     | 0.358 | 0.240 | 0.172 | **0.112** |
| Scratch | **0.122** | 0.385 | 0.334 | 0.199 | 0.150 |

**지금까지의 답**

- **RQ1**: 불량을 넣으면 좋아집니다. 다만 주 모델(DevNet) 기준 **종류당 8장**이 필요하고, 4장까지는 PatchCore와 같은 수준입니다. KNN+MLP는 K=1에서 K=0(kNN)보다 오히려 나빠집니다(4장으로 MLP가 과적합).
- **RQ2 (잠정)**: 교차 K = 8, 수확체감 K는 8 안에 없음, 목표 5%에는 8장으로도 못 미침(0.093). **최적 K는 "8 이상"** 이고, 8을 넘는 구간은 PCB2 Bent 풀(8장) 때문에 주 실험에서 잴 수 없습니다.
- **종류마다 필요한 K가 다릅니다.** Bent는 2장, Missing은 4장이면 PatchCore보다 훨씬 좋고(Missing 0.315 → 0.093), Scratch는 8장으로도 PatchCore보다 나쁩니다. → 결함 종류별 셋업 기간(6.5절)을 다르게 잡거나, Scratch·Melt는 PatchCore와 합치는(앙상블) 방향이 유망합니다 `[제안]`.
- PCB별로도 다릅니다: PCB1은 PatchCore가 0.067로 강해 DevNet K=8(0.087)도 넘지 못하고, PCB2는 DevNet K=2(0.077)에서 이미 PatchCore(0.210)를 넘습니다.

### 13.3 기본 증강: `classic`, `copypaste` (11/11)

| 모델    | 증강      | K=1   | K=2   | K=4   | K=8   | none 대비 (짝지은 차이, + = 증강이 좋음) |
| ------- | --------- | ----- | ----- | ----- | ----- | ---------------------------------------- |
| DevNet  | classic   | 0.316 | 0.235 | 0.158 | 0.106 | 모든 K에서 CI가 0을 포함 → **효과 없음** |
| KNN+MLP | classic   | 0.468 | 0.320 | 0.220 | 0.123 | **+0.055 ~ +0.095, 모든 K에서 유의미** |
| DevNet  | copypaste | 0.605 | 0.569 | 0.487 | 0.407 | **−0.27 ~ −0.34, 모든 K에서 크게 나빠짐** |
| KNN+MLP | copypaste | 0.647 | 0.608 | 0.534 | 0.442 | −0.08 ~ −0.26, 나빠짐 |

- **classic 등가 샘플 수** (none 곡선을 log K로 보간): KNN+MLP는 K=2+classic ≈ 실제 3.8장, K=4+classic ≈ 6.4장입니다. DevNet은 거의 1:1(K=4 → 3.8장)이라 효과가 없습니다. MLP처럼 과적합하기 쉬운 머리에서만 도움이 됩니다.
- **copy-paste는 해롭습니다. 원인 진단** (캐시된 임베딩으로 확인, DevNet):

  | 진단                                                     | 결과 |
  | -------------------------------------------------------- | ---- |
  | 실제 시험 불량 vs copy-paste 불량을 선형 분류기로 구분   | AUROC **0.989 / 0.970 / 0.954** (PCB1/2/3) → 특징 공간에서 생성 불량이 실제 불량과 따로 모여 있음 |
  | 생성 불량만으로 학습(cp_only)                            | K와 무관하게 FNR ≈ 0.6 → 생성 불량에서 배운 것이 실제 불량에 거의 옮겨지지 않음 |
  | 실제:생성을 배치에서 1:1로 뽑기(cp_1to1)                 | 0.539 / 0.483 / 0.410 / 0.330 → 그냥 섞기(0.605…0.407)보다 낫지만 none(0.341…0.093)보다 여전히 나쁨 |

  해석: 모델이 "copy-paste 흔적(덮어 붙인 경계, 원래 부품과 겹친 모양, 이미지 전체 임베딩의 분포 차이)"을 불량의 기준으로 배우고, 실제 불량에는 그 흔적이 없어서 놓칩니다(5.1절에서 걱정한 지름길). 구분 AUROC에는 종류 분포 차이(시험 불량은 Melt가 많음)도 일부 섞여 있습니다.
  다음 단계 `[제안]`: (1) 패치 단위 모델(PatchCore 변형, 4.2절 선택지)에서 copy-paste를 다시 보기 — 이미지 전체 임베딩보다 지름길에 덜 민감할 수 있음, (2) 생성 장수 10장(⑦ 선택 실험)으로 줄이기, (3) ctransgan이 오면 같은 진단(구분 AUROC)을 먼저 돌려 지름길 여부부터 확인.
